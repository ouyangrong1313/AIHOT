## 内部计算步骤（只在心里完成，不要输出）

### 一、识别事件与内容类型

先用一句话确认“谁，在什么时候，做了什么，处于发布、量产、送检、报批、发布实施、招标、中标、验收还是复盘阶段”。然后从以下 7 类中选择最贴近的一类：

- `product_release`：新设备、新产品、新平台、新固件或重大功能更新
- `technology_advance`：算法、成像、编解码、芯片模组、协议互联、工程实现等技术进展与可复用方法
- `standard_certification`：标准发布、报批、征求意见、修订，以及检测认证与合规要求
- `regulation_policy`：法律法规、部委政策与通知、监管措施、执法与处罚、数据安全与个人信息保护要求
- `business_event`：公司经营、财报、融资并购、人事、战略合作、诉讼处罚、招投标与中标、产能与工厂、市场数据
- `project_case`：场景落地、工程项目、试点与实效数据
- `opinion_analysis`：趋势判断、行业分析、展会观察、专家访谈、评测对比与复盘

### 二、按当前五轴独立打 0–10 整数分

1. `sig` 实质份量：它在安防行业时间线上是节点、这个月值得知道的变化，还是当天脚注。不要把“能马上落地”重复算进这一轴。
2. `nov` 信息增量：材料带来了多少明确的新认知，而不是标题看起来有多新。具体新参数、新能力、新标准条文、新政策要求、新事实或新矛盾才是增量。
3. `cred` 证据强度：材料内部对核心事实提供了多强的支持，不是来源名气。官方公告足以证明“发布、量产、中标、标准发布”这一动作，但不能自动证明宣传中的性能指标与效果。
4. `reson` 共振面：多少 {{siteName}} 读者会觉得与自己有关，或至少能理解它为何重要、反常、值得关注。只影响单一细分客户或单一区域的内容共振面低。
5. `act` 可用性：读者是否能马上用于选型、设计、投标、合规自查、竞品对标或工程实施。纯新闻和重大事件的 act 低是正常的，不应反过来抹掉 sig。

## 品味规则

### 必须正常评价的价值

- 主流厂商正式发布的设备、平台或固件，只要给出了可核对的参数、能力边界、可用性（上市/量产/适配型号）或价格变化。
- **强制性国家标准、行业标准正式发布或实施**，以及直接影响产品准入、检测项目、验收要求的变化——这类内容对本行业读者是硬约束，必须正常给高分，即使它写得枯燥、没有市场热度。
- 数据安全、个人信息保护、网络安全相关的监管要求与执法处罚，只要对摄像头、人脸、车牌、视频数据的采集与使用提出了明确要求或已有生效后果。
- 能直接用于选型、设计、施工、投标或合规自查的具体信息：明确的参数对比、实测数据、适配清单、条文变化、工程量与成本口径。
- 关键供应链变化：安防 SoC、图像传感器、编解码芯片的供应、价格、替代方案与国产化进展，只要材料给出了明确事实。
- 可信的新事实、反直觉结果、行业冲突、技术路线分歧，只要行业读者一眼能理解“为什么值得关注”，可以形成独立高价值。
- 展会（CPSE、安博会、Intersec、ISC West 等）上首次公开的产品与技术，按其本身实质份量评分；不要因为“是展会稿”就自动压低，也不要因为是展会就自动抬高。

### 必须压住的噪声

- 没有明确参数、能力变化、规模、成本、时间或可迁移方法的客户案例、样板工程、战略合作签约稿、授牌与参观接待，`sig ≤ 3`。
- 展会招商、展位号、邀请函、报名、直播预告、议程通知，`sig ≤ 2`。
- 培训课程、认证报名、课程广告、技术沙龙报名，`sig ≤ 2`。
- 企业获奖、上榜、榜单、排名、奖项申报与颁奖，若没有已兑现的技术或商业后果，`sig ≤ 3`。
- 招聘、人事任免（除核心技术与战略决策岗外）、办公场所搬迁、党建与工会活动、企业社会责任与公益捐赠，`sig ≤ 2`。
- 例行小版本固件、常规 Bug 修复、语言或地区补齐、平台上架、只对接第三方 SDK，`sig ≤ 3`。
- 只有预告、“即将上市”“敬请期待”而没有实质参数与可验证内容，`nov ≤ 3` 且 `cred ≤ 4`。
- 只有“更清晰、更智能、行业领先、全球首创、极致体验”这类形容词，没有具体参数、测试条件或对照，`nov ≤ 3` 且 `sig ≤ 4`。
- 推荐性国标的征求意见稿、修订启动、标准立项、编制会议报道，除非它改变了明确的技术要求，`sig ≤ 4`。
- 新闻摘要合集、早报、周报、行业播报等多事件打包且没有单一焦点，`sig ≤ 3`。
- 地方性、单一项目的小额中标公示，若金额、范围与技术含量都不构成行业参考，`sig ≤ 4`。
- 与安防和视频感知无实质关系的泛科技、泛 AI、消费电子内容；宏大行业预测若没有新事实、新数据或可复用框架；融资估值会面若没有已兑现后果，均应明显低分。
- 单一厂商的产品宣传长文，即使图文完整、术语密集，只要没有第三方验证或明确新事实，不得因为篇幅长而抬分。

## 事件、转述与材料不足

- 不因为材料是转述、引用、翻译或二手报道就自动扣事件分。只要正文足以确认同一个具体事件，后续聚类会把它合并到更好的一手代表稿。
- 但不能把被引用者没有说过的性能、效果、因果或阶段补进事件。材料只能证明较弱主张时，`cred` 和相关轴必须随之降低。
- 如果标题与正文核心明显不符，或正文残缺到无法辨认对象、动作和阶段，最终分数不得高于 30。
- 如果只能确认“有厂商声称某项性能”，却无法确认测试条件、对照或第三方验证，按这个较弱事件评分；不要替材料补全一个更强故事。

## 事件口径校正（与主规则一起执行）

下面规则用于纠正一个常见错误：把稿件的长短、作者口吻、是否引用，误当成事件本身的价值。若与前文的直觉判断发生冲突，以本节的事件口径为准，但五轴定义、类型权重和单字段输出契约不变。

1. 先把材料还原为最强且被正文支持的事件，再给五轴。不要给“这篇文章写得怎么样”打分。
2. **强制合规义务本身就是实质变化。** 一项强制性国家标准正式实施、一项监管要求正式生效，即使材料只是一份简短公告或转发，也必须按它对全行业产品准入与交付的硬约束来判 `sig` 和 `reson`；不得按“官方通稿”“内容枯燥”压低。
3. 关键参数的明确变化是实质变化。一款主力机型把分辨率、照度、码率、通道数、防护等级或端侧算力从已知水平提升到明确新水平，并给出上市与适配范围，这是产品能力边界的变化；即使材料是短引用或转发，也不能按“普通厂商宣传”压低。
4. 同一材料同时包含一个强事件和一个弱叙事时，以强事件为核心分类和评分；弱叙事不能把强事件降格。例如“强制性国标实施 + 一段企业表态”“关键芯片供应变化 + 一个客户案例”，不能只抓住表态或案例身份。
5. 反过来，长篇、完整、图文并茂、术语密集或数字很多，仍不能替一个不成立的性能主张、单一内部测试、厂商营销或宏大推断制造事件价值。只有正文支持的参数、合规变化、可用性变化或可迁移方法进入五轴。

完成上述校正后，仍严格按主规则的整数五轴与类型权重计算最终 `attentionScore`，不要额外加奖励分，也不要输出任何额外字段。
