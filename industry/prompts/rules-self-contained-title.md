
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：厂商名 / 产品名与型号 / 标准编号 / 机构名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "V5.7.12"、"新品上市"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "V5.7.12" + 来源 "某厂商固件下载页" → "某厂商 NVR 固件 V5.7.12 发布"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"低照度网络摄像机""强制性国家标准"）兜底，绝不凭"行业常识"编一个具体型号 / 版本 / 参数 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的模型、产品或新数据，就改写成“发布 / 推出 / 上线 / 开源”。只有原标题明确宣布了发布、推出、上线或开源，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、产品、项目名。
   例：原标题 "How AcuSense cuts false alarms in real deployments" → "AcuSense 如何在实际部署中降低误报"，不能写成 "海康威视发布 AcuSense"。
   例：原标题 "选型指南：如何在低照度场景选对机型" + 来源和正文明确是某厂商 → "某厂商低照度场景机型选型指南"，不能只写成缺主体的 "低照度场景机型选型指南"。
